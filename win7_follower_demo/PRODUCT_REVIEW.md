# SO101 Win7 Follower Demo 产品评审

## 结论

当前项目已经具备“可运行的工程演示”能力，但还没有达到“合格产品层”。
它的主要问题不是功能缺失，而是任务闭环不清、状态语义不统一、危险操作边界不够明确、配置与文档不一致。

## 合格产品层定义

一个合格产品至少应满足以下条件：

1. 新用户按文档可一次跑通首个成功路径。
2. 用户始终知道当前处于什么模式、下一步该做什么、点下去会发生什么。
3. 所有可能影响真实机械臂的操作都有明确边界和可恢复路径。
4. 失败时给出可操作的错误提示，而不是只报工程状态。
5. 文档、默认配置、UI 文案和实际行为保持一致。

## 缺陷分层

### P0 级: 安全与误操作风险

问题：

- “停止”按钮语义不准确，当前更像清 busy / 释放力矩，不等于硬件急停。
- 真实硬件模式下，用户容易误判哪些操作会写入机械臂，哪些只是预览。
- 监视模式、动作模式、初始化状态这些概念同时存在，但对用户没有统一解释。

影响：

- 一旦现场演示出错，用户无法快速判断是否需要断电或手动介入。
- 误操作成本高，产品可信度低。

改进方向：

- 把停止拆成“暂停 / 释放力矩 / 急停说明”三个明确语义。
- 在首屏增加硬件风险状态区，直接显示“当前是否会写入硬件”。
- 对所有真实执行动作增加二次确认和明显的危险提示。

### P1 级: 核心任务闭环不完整

问题：

- 用户路径没有被组织成明确步骤。
- 连接、切模式、初始化、录制、保存、回放、手动控制分散在多个区域。
- 回放前需要动作模式并初始化，但页面没有把这个前置条件做成流程引导。

影响：

- 新用户不知道先点什么，常见结果是“界面看起来很多按钮，但不知道怎么开始”。
- 演示成功率依赖操作者经验，不符合产品要求。

改进方向：

- 重构为步骤式流程：连接 -> 确认模式 -> 初始化 -> 执行动作 -> 结束。
- 首屏只保留最关键的主操作按钮，其余功能折叠或次级化。
- 每个按钮旁给出明确前置条件和结果说明。

### P2 级: 一致性与可理解性不足

问题：

- README 的默认端口、默认模式与当前配置不一致。
- UI 中同时出现英文状态、工程术语和中文操作词。
- 录制名称输入框是只读的，但界面又暗示用户可以命名。
- 文件与模板两个概念都暴露给用户，导致重复和混淆。

影响：

- 用户会把失败归因于系统不稳定，而不是配置不一致。
- 后续管理录制内容成本高，找动作和删动作都不直观。

改进方向：

- 统一 README、默认配置、UI 文案和实际启动端口。
- 将“文件/模板”统一成用户能理解的“动作库”。
- 允许用户真正命名录制内容，或明确只采用系统自动命名。

### P3 级: 体验与视觉层问题

问题：

- 页面是一个信息密度很高的控制台，但视觉层仍带有较强展示风格。
- 状态区、事件区、模板区都占据较多空间，但缺少优先级。
- 局部提示文字偏长，阅读成本高。

影响：

- 控制台扫描效率不高。
- 现场演示时不够“稳”，容易给人临时拼接的印象。

改进方向：

- 降低装饰性，强化状态优先级。
- 让主流程区域更突出，次要日志区折叠或收起。
- 用更短、更确定的文案替代解释型长句。

## 当前优先级建议

1. 先修正停止语义和安全边界。
2. 再把首屏改成步骤式任务流。
3. 然后统一文档、配置、UI 术语。
4. 最后再处理视觉和信息密度。
