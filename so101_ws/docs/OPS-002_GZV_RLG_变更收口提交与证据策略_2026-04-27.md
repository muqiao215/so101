## 2. Evidence 与 vision-episodes 入库策略

`docs/evidence`：

- 入库：人工截图、短日志、验证记录 Markdown、能证明前端/链路状态的少量 PNG。
- 不入库：重复截图、临时浏览器录屏、可由脚本重建的大日志。
- 当前建议保留：`gzv-004-vision-targets-frontend-20260427.png`、`gzv-frontend-vision-connected-20260427.png`、`gzv-developer-workbench-20260427.png`，分别覆盖 target 坐标、仿真视觉全栈、开发工作台来源语义。

`docs/generated/vision-episodes`：

- 入库优先级：`manifest.json`、`validation-report.json`、`REPORT.md`、`dataset/dataset-index.json`、`dataset/lerobot-candidate/manifest.json`。
- 默认不入库：image snapshots、`events.jsonl`、`samples.jsonl`、`train_samples.jsonl`、`debug_samples.jsonl`、重复 smoke episode 全目录。
- 推荐只保留一个 golden smoke 目录的轻量摘要：`gzv011_status_heartbeat_smoke_20260427_010757`，因为该轮 `dataset validation passed` 且 `train_sample_count=9`、`debug_sample_count=0`。
- 较早 smoke 目录如 `gzv005_*`、`gzv010_*` 可作为本地排查证据，不建议全量提交；若需要可放入压缩证据包并在 `docs/evidence` 写索引。

## 3. 提交切分建议

建议按依赖顺序切分，避免一个提交同时包含前端、后端、ROS、数据集产物和策略文档。

1. `ops: add gzv rlg closeout policy`
   - 包含本文件、`tools/evidence/classify_git_status.py`、`docs/任务清单.md`、`docs/进度日志.md` 的 OPS-002 更新。
2. `gzv: add gazebo vision capture runtime`
   - 包含 Gazebo camera、sim color detector、vision target projector、vision episode recorder、launch 与 e2e 启动参数。
3. `gzv: add vision episode validation and dataset export`
   - 包含 `validate_vision_episode.py`、`build_vision_dataset_adapter.py`、`export_vision_dataset_to_lerobot_candidate.py` 及对应测试。
4. `gzv: surface simulated vision in mes ui`
   - 包含后端 rosbridge `/vision/targets`、runtime launch 语义、前端视觉控制台、heartbeat 降噪及测试。
5. `rlg: add leader to gazebo bridge offline smoke`
   - 包含 RLG bridge、launch、recording replay 相关 ROS 文件、RLG 测试与计划文档更新。
6. `docs: keep selected gzv evidence`
   - 只加入人工筛选后的 PNG/Markdown 小证据；不要顺手加入整份 generated episode。

如果某些文件同时服务 GZV 与 RLG，例如 `sim_bringup.launch.py` 或 `package.xml`，按“首个引入功能”所在提交放入，并在提交说明中列出后续提交复用该入口。

## 5. 收口门槛

- `python3 tools/evidence/classify_git_status.py` 输出中不应出现未知的大型二进制或未归类核心代码。
- `docs/generated/vision-episodes` 只允许提交人工筛选的轻量摘要，除非明确要把某个 golden episode 作为版本化 fixture。
- 每个提交都必须能用本节测试清单中的相关子集解释，不把“仅本地跑过”当作证据。
- 不把真实硬件未验证的内容标为 `done`；RLG live 真机输入未测时继续保持 `in_progress`。
