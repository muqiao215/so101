# HWP-004 真机目录接入烟雾验证

## 目标

在真机目录刚拿到时，不先改 backend 主逻辑，不先改前端，不先放行动作。

先做一件事：

- 用一份 target config 把真机目录里的状态源接进 smoke harness
- 验证它能不能被当前 contract 正常吃下
- 同时把结果落成 report 和运行时 contract 文件

## 本轮交付

### 1. Target Config 驱动的 smoke 脚本

- 文件：`tools/hardware/real_hardware_adapter_target.py`
- 作用：
  - 读取 target config
  - 从真实来源加载状态
  - 归一化为 HWP-003 contract
  - 写出 smoke report
  - 写出运行时 contract 文件

### 2. Target Config 示例

- 文件：`tools/hardware/real_hardware_adapter_target.example.json`
- 文件：`tools/hardware/real_hardware_adapter_target.command.example.json`

支持两类真实来源：

- `source.type = file`
  - 适用于“真机目录里已经有状态 JSON 文件”
- `source.type = command`
  - 适用于“真机目录提供一个命令，执行后吐 JSON”

### 3. 原始状态源示例

- 文件：`tools/hardware/real_hardware_status_source.example.json`

这个文件不是运行时 contract，而是“真实目录最好至少能吐出这种结构”的参考。

### 4. Smoke 产物

运行后至少会产生：

- `.vscode/.runtime/real_hardware_status.json`
- `.vscode/.runtime/real_hardware_command_gate.json`
- `.vscode/.runtime/real_hardware_adapter_smoke_report.json`

## 运行方式

### 文件型来源

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws

export SO101_REAL_HW_STATUS_PATH=/ABS/PATH/TO/REAL_HARDWARE/status.json
bash tools/hardware/run_real_hardware_target_smoke.sh \
  tools/hardware/real_hardware_adapter_target.example.json
```

前提：

- 给 `SO101_REAL_HW_STATUS_PATH` 赋值
- 或者直接复制 example 后改成固定路径

### 命令型来源

推荐直接使用：

- `tools/hardware/real_hardware_adapter_target.command.example.json`

也可以手写成：

```json
{
  "adapterId": "so101-real-hardware",
  "source": {
    "type": "command",
    "command": "python3 /ABS/PATH/TO/real_hw/export_status.py"
  },
  "gate": {
    "enabled": false,
    "reason": "HWS-002 未通过，默认锁执行",
    "source": "so101-real-hardware"
  }
}
```

## 当前默认策略

- smoke 只做“接入验证”，不做动作放行
- target config 里的 `gate.enabled` 默认应保持 `false`
- 真机目录即使回报 `allowExecute=true`，后端最终也仍会被 gate 压回 `false`
- smoke report 现在会额外输出：
  - `checks.sourceLoaded`
  - `checks.statusFileWritten`
  - `checks.gateFileWritten`
  - `checks.gateLocked`

## 验证通过代表什么

通过后，只代表：

- 真机目录的状态源格式可被系统接收
- 当前 contract 可被写出
- backend 读取路径已经打通

不代表：

- 真机已经安全
- 真机已经允许执行
- 真机已经完成校准

## 明天拿到真机目录后的最短顺序

1. 复制 `tools/hardware/real_hardware_adapter_target.example.json`
2. 优先使用环境变量：
   - `SO101_REAL_HW_STATUS_PATH`
   - 或 `SO101_REAL_HW_STATUS_CMD`
3. 保持 `gate.enabled=false`
4. 跑 `run_real_hardware_target_smoke.sh`
5. 看 `real_hardware_adapter_smoke_report.json`
6. 再决定是否进入 `HWS-001/HWS-002`
