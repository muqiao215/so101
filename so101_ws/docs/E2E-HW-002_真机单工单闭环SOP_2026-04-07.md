# E2E-HW-002 真机单工单闭环 SOP

更新时间：2026-04-07

## 1. 目标

在真机受控、低速、安全边界内，完成一张真实工单的最小闭环：

- MES 创建工单
- MES 下发工单
- 真机执行固定模板
- 状态回传
- 前端或 API 可见最终结果

本阶段仍坚持：

- 先单工单，后复杂联动
- 先固定模板，后视觉抓取
- 先单次受控执行，后连续运行

## 2. 本 SOP 的边界

本 SOP 只做：

- 单工单
- 固定模板
- 主臂
- 低速、单次、受控验证

本 SOP 不做：

- 视觉抓取
- 自由抓取
- 多工单并发
- 首页改版
- 任意模板批量回归

## 5. 最小闭环命令

### Step 1: 创建工单

```bash
curl -fsS -X POST http://127.0.0.1:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{"orderId":"order-hw-001","actionTemplateId":"pick_place_red"}'
```

通过标准：

- HTTP 成功
- 返回体中 `state=PENDING`

### Step 2: 下发工单

```bash
curl -fsS -X POST http://127.0.0.1:8080/api/orders/order-hw-001/dispatch \
  -H "Content-Type: application/json" \
  -d '{"priority":1}'
```

通过标准：

- HTTP 成功
- 返回体中：
  - `ok=true`
  - `requestId` 存在

### Step 3: 观察状态流

至少观察两处：

1. API：

```bash
curl -fsS http://127.0.0.1:8080/api/orders/order-hw-001
```

2. 前端：

- 工单卡片状态
- 实时状态流

理想状态流：

- `PENDING`
- `RUNNING`
- `DONE`

如果失败，也必须能看到可解释状态，而不是静默卡死。

## 7. 风险控制

本 SOP 进入真实单工单执行前，必须明确一个现场决定：

- 是否开启“单次受控执行窗口”

如果当前仍决定继续锁执行，则本 SOP 只能完成：

- 创建工单
- 下发工单
- 验证状态机与保护态反馈

不能宣称“真机执行闭环已完成”。

如果进入单次受控执行窗口，执行后应立即回到保护态，并复核：

- `allowExecute`
- `commandExecutionEnabled`
- 当前姿态
- 最近错误
