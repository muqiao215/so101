# HWP-002 真机最小 Bringup 软件准备

## 目标

在真机目录尚未接入前，先把 SO101 的真机最小 bringup 软件面准备好，保证系统默认处于“保护态”，并且可以通过 CLI 完成预检、启动、停机和状态展示。

## 当前原则

- 先保命，后动作。
- 真机链路未校准前，默认 `allowExecute=false`。
- 真机链路未验证前，默认关闭：
  - 自动检测触发
  - `/mes_task_cmd` 动作执行
- 首页只展示状态，不承担第一轮放行动作。

## 已落地的软件骨架

### 1. 命令执行闸门

- 文件：`src/so101_bringup/scripts/task_executor.py`
- 新参数：`command_execution_enabled`
- 行为：
  - `false` 时拒绝执行 `/mes_task_cmd`
  - 返回状态码：`COMMAND_LOCKED`
  - 同时禁用检测触发自动执行

### 2. 真机状态文件

- 文件：`.vscode/.runtime/real_hardware_status.json`
- 写入工具：`tools/hardware/write_real_hardware_status.py`
- 当前字段：
  - `online`
  - `controlInterface`
  - `powerState`
  - `estopActive`
  - `mode`
  - `lastError`
  - `allowExecute`
  - `updatedAt`

### 3. CLI 软件预检入口

- `tools/hardware/prepare_real_bringup.sh`
  - 写入安全默认状态
  - 检查 `real_bringup.launch.py` 参数

- `tools/hardware/start_real_min_bringup.sh`
  - 以安全默认值启动真机最小 bringup
  - 默认：
    - `detection_trigger_enabled:=false`
    - `command_execution_enabled:=false`
  - 启动后增加 2 秒存活检查，避免后台 launch 秒退时仍误报成功

- `tools/hardware/stop_real_min_bringup.sh`
  - 停止最小 bringup
  - 同步回写安全待机状态

## 当前已验证结果

- `prepare_real_bringup.sh` 已成功输出：
  - `.vscode/.runtime/real_bringup_build.log`
  - `.vscode/.runtime/real_bringup_preflight.log`
- `real_bringup_preflight.log` 已确认首轮真机 bringup 具备：
  - `command_execution_enabled`
  - `detection_trigger_enabled`
  - `detection_confidence_threshold`
  - `detection_trigger_cooldown_sec`
- `start_real_min_bringup.sh` 已能进入受限 launch 路径，并在日志中看到：
  - `Command gate: enabled=False`
  - `detection trigger: enabled=False`
- `real_hardware_status.json` 当前可稳定表达“未上电 / 保护待机 / 不允许执行”。

## 当前限制

- 当前验证发生在 Codex 沙箱内，网络与后台进程存在隔离限制。
- 因此这轮证据只能证明：
  - 软件预检脚本可运行
  - 安全默认值已落地
  - 执行闸门确实关闭
- 这轮还不能证明：
  - 真机驱动已接入
  - 后台 bringup 可在真实终端长期驻留
  - `/api/system/status` 已连上真实硬件状态源
