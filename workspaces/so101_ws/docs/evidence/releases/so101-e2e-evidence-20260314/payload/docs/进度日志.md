### 核心排坑经验（非常重要）

历经长时间拉锯调试，总结出在非 xacro 原生环境下使用 `gazebo_ros2_control` 的致命坑点及完整解法：

1. **URDF 的 xacro 语法解析陷阱**：
   - `gazebo_ros2_control` 插件需要 `<parameters>$(find ...)/controllers.yaml</parameters>`。
   - 坑点：如果不是实时通过 xacro 转换，直接把 `$(find...)` 明文写进 `.urdf`，Gazebo 加载插件时或 `spawn_entity` 解析时会崩溃报错。
   - 解法：在 URDF 中使用占位符 `__CONTROLLERS_YAML__`，在 `launch.py` 启动阶段读取 URDF 文本，用 Python 动态替换为绝对路径文本，再传给 `robot_description`。
2. **`rcl` 参数解析器与 XML 注释冲突 (`--` 导致崩溃)**：
   - 坑点：`rcl`（ROS 2 核心系统）在处理传入参数（如超长 `robot_description` 字符串）时极其脆弱。如果 URDF 内部带有标准 XML 注释 `<!-- ... -->`，其中的 `--` 会被 `rcl` 的命令行解析器误当做非法 flag（报错：`Couldn't parse parameter override rule`），导致节点直接闪退。
   - 解法：在 `launch.py` 中向 `robot_description` 赋值前，用正则 `re.sub(r'<!--.*?-->', '', urdf_content, flags=re.DOTALL)` 把所有 XML 注释彻底剥离。
3. **`spawn_entity.py` 启动顺序与姿势**：
   - 用 `-topic robot_description` 而非 `-file`。
   - 必须设置延迟启动（`TimerAction` 延时 4-5 秒），等待 `gzserver` 与 `gazebo_ros_factory` 完全就绪，否则会引发 `/spawn_entity` 服务拒绝连接或超时。
4. **`CONTROL_FAILED` 与位置接口的 PID 配置**：
   - 现象：轨迹发送后直接报错取消，机械臂呈现不受力的软倒地状态。
   - 坑点：`gazebo_ros2_control` 仿真若使用默认的位置接口，**必须**在 `controllers.yaml` 中为 `joint_trajectory_controller` 提供 PID 增益（`p, i, d, i_clamp` 等），否则控制器不输出计算出的力。
5. **初始化自碰撞导致 MoveIt2 罢工**：
   - 现象：启动时 MoveIt2 提示 `Start state in collision`，拒绝任何轨迹规划。
   - 坑点：机械臂处于默认位姿时，某些连杆（如 `lower_arm` 与 `gripper`）可能因简化几何体相交产生自碰撞。
   - 解法：全面排查并在 `SRDF` 中的 `<disable_collisions>` 追加所有潜在碰撞的连杆对（即使它们在 URDF 的动力学树中不相邻）。

### 验证步骤

1. 单独启动 Gazebo 环境，验证 `ros2 control list_controllers` 返回活跃的 `joint_trajectory_controller`。
2. 运行 `pick_place_runner.py --iterations 20`，机械臂在 Gazebo 中可以完成 20 轮连续稳定抓取与放置流程。

1. **sympy 版本冲突**：
   - 现象：`cannot import name 'equal_valued' from 'sympy.core.numbers'`
   - 原因：`ultralytics` 要求 sympy ≥1.12，但系统 apt 装的是 1.9（`/usr/lib/python3/dist-packages/sympy`）。`pip install --upgrade sympy` 装到了 `~/.local/lib/python3.10/site-packages/`，但 ROS2 launch 环境的 PYTHONPATH 优先加载系统级包。
   - 解法：在 `yolov8_detector.launch.py` 中用 `SetEnvironmentVariable("PYTHONPATH", user_site + ":" + ...)` 把用户 `~/.local` 前置。
   - **更优解法（待执行）**：配置 `sudo visudo` 允许 `muqiao ALL=(ALL) NOPASSWD: ALL`，然后直接 `sudo pip3 install sympy==1.12` 升级系统级包，避免 PYTHONPATH 前置带来的副作用。

2. **numpy 2.x 与 cv_bridge 不兼容**：
   - 现象：`AttributeError: _ARRAY_API not found`（从 `cv_bridge` 抛出）
   - 原因：`ultralytics` 拉入 numpy 2.2.6 到 `~/.local`，但 ROS2 的 `cv_bridge` C++ 扩展是用 numpy 1.x ABI 编译的。上述 PYTHONPATH 前置后，numpy 2.x 优先加载导致崩溃。
   - 解法：手动删除 `~/.local/lib/python3.10/site-packages/numpy*`，回退到系统级 numpy 1.21.5。

3. **yolov8n.pt 模型下载**：
   - 首次运行会从 GitHub releases 下载模型，国内网络可能 SSL 超时。
   - 重试后成功下载，模型缓存在当前工作目录。

### 环境建议（待执行）

- **设置 sudo 免密码**：

  ```bash

  # 末尾追加：
  muqiao ALL=(ALL) NOPASSWD: ALL
  ```

  理由：后续系统级 pip 升级 / apt 安装操作频繁，免密可避免 Agent 交互卡住。
  配置后可直接 `sudo pip3 install sympy==1.12` 替代当前的 PYTHONPATH 前置方案。
