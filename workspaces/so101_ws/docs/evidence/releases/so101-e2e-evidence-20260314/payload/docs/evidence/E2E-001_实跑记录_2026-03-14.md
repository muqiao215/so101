## 根因判断

最小根因在 `tools/e2e/start_e2e_stack.sh` 的 ROS2 启动方式。

脚本当前直接执行：

```bash
nohup ros2 launch so101_bringup sim_bringup.launch.py ...
```

但没有为 `ros2 launch` 设置可写的 `ROS_LOG_DIR`。在本次环境中，`ros2 launch` 默认尝试写入：

```text
/home/muqiao/.ros/log/...
```

结果因为权限被拒绝而直接退出，导致脚本卡在 ROS2 阶段反复做端口探测，表面输出为：

```text
Cannot open netlink socket: Operation not permitted
```

因此：

- 这次不是 backend 或 frontend 业务失败
- 也不是 `stop_e2e_stack.sh` 的问题
- 最小根因是 `start_e2e_stack.sh` 未处理 `ros2 launch` 的日志目录权限前置条件
