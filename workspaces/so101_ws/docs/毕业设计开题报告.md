课题名称

  基于ROS2和LeRobot SO-101的小型智能制造MES系统设计与实现

  课题来源：科学技术

  成果形式：实做类毕业设计

  -----------------------------------------------------------------------------------------------------------------------------------------------------------

  1 研究的目的

  随着"中国制造2025"战略的深入推进，智能制造已成为制造业转型升级的核心方向。制造执行系统（Manufacturing Execution System, MES）作为连接企业资源计划（ERP）与车间层设备控制的关键桥梁，在现代工业生产中发挥着不可替代的作用[1]。然而，当前工业级MES系统通常造价高昂、部署复杂，对于高校教学演示和中小型企业的技术验证而言存在较高的门槛。

  与此同时，开源机器人操作系统ROS2（Robot Operating System 2）凭借其分布式通信架构、实时性支持和丰富的生态工具，已逐渐成为机器人研发领域的标准化平台[2]。2024年，Hugging Face联合TheRobotStudio推出了开源低成本机械臂SO-101（项目仓库命名为SO-ARM100）及配套的LeRobot软件框架，使得具备6自由度的桌面级机械臂的获取成本大幅降低[3][13]。Google DeepMind的MuJoCo物理仿真引擎也已为该机械臂提供了官方仿真模型，为离线调试和虚拟验证创造了条件[4]。

  本课题的研究目的在于：基于ROS2机器人操作系统，以SO-101开源机械臂为执行终端，结合YOLO目标检测算法、Java Spring Boot框架与rosbridge通信中间件，设计并实现一套小型智能制造MES演示系统。该系统将涵盖工单管理、视觉检测、机械臂预设轨迹执行、状态反馈等核心功能闭环，力求以低成本、开源化的方式，完整复现工业MES的基本工作流程，为机电一体化专业的教学实践提供可操作的实物演示平台，同时验证ROS2在轻量级智能制造场景中的可行性。

  2 主要研究内容

  本课题围绕"感知—决策—执行—反馈"的工业闭环逻辑，主要研究以下内容：

  （1）SO-101机械臂的ROS2系统集成

  基于TheRobotStudio官方提供的SO-101 URDF（统一机器人描述格式）模型和STL三维网格文件，构建符合ROS2规范的机器人描述包（so101_description）。利用robot_state_publisher和joint_state_publisher实现关节状态发布，在RViz2中完成模型可视化验证。进一步通过ros2_control框架配置关节位置控制器，实现ROS2 Topic对机械臂6个关节（shoulder_pan、shoulder_lift、elbow_flex、wrist_flex、wrist_roll、gripper）的统一控制接口[5]。

  （2）仿真环境搭建与轨迹规划

  采用Gazebo物理仿真器加载SO-101模型，构建包含工作台、料盒等元素的虚拟工位场景。利用MoveIt2运动规划框架配置运动学求解器（KDL）、规划组和碰撞矩阵，在仿真环境中完成Pick-Place（取放料）预设轨迹的规划与验证[6]。同时引入MuJoCo仿真器作为辅助验证工具，利用官方MJCF模型进行快速动力学验证[7]。规划后的关节轨迹将以YAML配置文件形式存储，供真机执行时直接调用。

  （3）基于YOLO的视觉检测模块

  部署YOLOv8n（nano版本）目标检测模型，通过USB摄像头采集工位图像，实时检测物料的类别和位置[8]。检测节点以ROS2 Node形式运行，订阅摄像头图像话题（/camera/image_raw），发布检测结果话题（/detections）。检测结果用于两个方面：一是触发对应的预设动作程序（如根据物料类别选择不同放置位置），二是将检测画面和结果推送至MES前端页面进行展示。YOLO模型采用COCO预训练权重，必要时使用Roboflow平台进行小样本微调[9]。视觉抓取策略方面，本课题采用“视觉分类触发+固定工装定位”的降级方案：视觉模块仅负责物料类别识别与在位确认，物料的精确空间位置由治具槽位或料盒格子等固定工装保证，机械臂执行预设轨迹到固定点位完成抓取。该方案无需完整的手眼标定（Eye-in-Hand或Eye-to-Hand外参求解），降低了系统复杂度，同时保证了演示的可靠性。后续如需扩展至任意位置抓取，可引入相机内参标定、平面单应性映射或Tsai-Lenz手眼标定方法实现图像坐标到机器人坐标的转换[15]。

  （4）MES系统Web后端与前端开发
  后端采用Java Spring Boot框架开发，基于Spring MVC提供RESTful API、基于Spring WebSocket提供实时推送能力[10]。系统采用“MES应用层与ROS2设备控制层进程分离”架构：MES后端仅负责业务编排与状态管理，不直接嵌入rclpy/rclcpp，而通过rosbridge_suite提供的WebSocket-JSON协议与ROS2侧交互[16]。该设计可降低框架耦合度，避免在同一进程内混合Web请求线程与ROS2执行器带来的并发复杂性，便于后续独立扩容与故障隔离。

  功能上，后端包含工单管理（CRUD）、任务下发、执行状态跟踪、检测结果转发、生产统计五个模块。任务下发采用“工单ID + 动作模板ID + 参数”的结构化消息模型，经rosbridge发布至约定话题；状态回传统一映射为“待执行/执行中/完成/异常”四态，保证前后端与ROS2侧语义一致。数据持久层采用Spring Data JPA，数据库选用SQLite（单机演示）或MySQL（多终端并发）以适配不同部署规模。

  前端采用Vue.js开发响应式页面，通过HTTP接口完成工单与统计查询，通过WebSocket接收任务状态与检测结果增量更新[11]。页面支持Windows浏览器直接访问，无需专用客户端，可满足教学演示场景下的上位机需求。
  （5）系统集成与闭环验证

  将上述各模块整合为完整的工作流：MES页面创建工单→YOLO检测确认物料就位→ROS2节点调度预设轨迹→机械臂执行Pick-Place动作→动作完成状态回传MES→页面更新工单状态并记录统计数据。在Gazebo仿真环境中完成全链路联调后，切换ros2_control硬件接口连接SO-101真机，验证仿真到实机的控制接口一致性与迁移可行性[12]。

  3 课题的准备情况

  （1）硬件准备

  已规划SO-101机械臂套件（含STS3215 Feetech舵机、Waveshare电机控制板）、USB摄像头、5V/5A独立电源、USB Hub等硬件设备。SO-101作为Hugging Face与TheRobotStudio联合设计的开源机械臂，拥有完善的BOM清单和全球多渠道供货[3]。

  （2）软件环境
  已部署Ubuntu 22.04操作系统及ROS2 Humble桌面完整版，具备Gazebo、RViz2、colcon等工具链。已在本地ROS2工作空间（~/dev/ros2/workspaces/so101_ws/）中完成如下准备工作：克隆TheRobotStudio/SO-ARM100官方仓库；基于官方URDF构建so101_description ROS2包并修正mesh引用路径；配置so101_mujoco包（含官方MJCF模型和可视化脚本）；调研LeRobot与ROS2桥接实现方案[14]。
  （3）技术储备
  本人在前期课程和项目中已掌握ROS2节点编程、话题通信、Launch文件编写等基本技能，具备FishBot移动机器人的开发经验。具备Python和Java Web开发基础，了解Spring Boot框架和Maven构建工具。YOLO目标检测方面，ultralytics库提供了开箱即用的推理接口，部署门槛较低[8]。

   (4)在系统工程能力方面，已具备从“功能原型”到“可演示闭环”的分阶段实施经验，能够按“先单机仿真、后软硬解耦、再端到端联调”的路径推进开发。针对本课题拟采用任务分解和证据化管理方法：将机械臂控制、视觉检测、后端通信、前端展示拆分为可独立验证的子模块，每个模块均以“输入、处理、输出、异常”四要素定义验收标准，并通过日志、话题回放、接口测试结果形成可追溯证据。该方法可降低多模块并行开发时的联调不确定性，提高阶段性成果的可解释性与复现性。

  (5)在ROS2与Web融合实现方面，已理解并实践“控制面与业务面分离”的工程原则：ROS2侧负责实时控制与状态发布，Web侧负责流程编排与数据展示，中间通过rosbridge进行协议转换，避免将实时控制逻辑直接耦合到Web请求线程。该架构不仅有助于降低并发复杂度，也便于后续扩展，例如替换视觉模型、增加新的工位动作模板、引入多终端监控页面等。针对毕业设计答辩场景，还将补充一键启动脚本、异常重试策略和演示检查清单，确保系统在实验室环境下具备稳定复现实验结果的能力。

  (6)在算法与模型应用层面，已具备将开源模型工程化落地的基础能力：包括数据采集与标注、阈值调参、推理性能评估、结果可视化和误检漏检分析。考虑到本课题以教学演示为核心目标，视觉模块将优先保障“类别识别稳定性”和“触发逻辑可解释性”，而非追求复杂抓取位姿估计，从而在有限周期内实现可运行、可展示、可复现的系统结果。同时预留后续升级路径：在完成固定工装抓取后，可逐步引入相机标定、坐标转换和闭环伺服策略，以支撑更高难度的自主抓取任务。
