## 1. 一键启动整套项目

进入工作区根目录：

```bash

```

默认启动整套栈：


说明：

1. 当前默认入口已经切到“可见仿真演示模式”
2. 这套命令会启动或复用 ROS2 仿真链
3. 会启动或复用 `mes_backend`
4. 会启动或复用 `mes_frontend`
5. 停止时默认也走 `bash tools/e2e/stop_visible_demo_stack.sh`

正常输出里应出现：

```text

backend:  http://127.0.0.1:8080
rosbridge: ws://127.0.0.1:9090
```

## 3. 前端页面手动验证流程

页面打开后，按这个顺序操作：

1. 确认 Step 1 显示仿真已启动
2. 确认 Step 2 显示 rosbridge 已连接
3. 点击 `连接实时状态`
4. 等页面显示 `实时状态 -> 已连接`
5. 动作模板保持默认：`pick_place_default`
6. 点击 `创建并下发工单`
7. 观察页面里的工单状态和状态时间线

理想状态流：

```text
DISPATCHED -> STARTED -> STEP ... -> OK
```

## 4. 分开启动的命令

如果不想用一键脚本，可以手动分别启动。

### 4.1 启动 ROS2 仿真链

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ROS_LOG_DIR=/home/muqiao/dev/ros2/workspaces/so101_ws/.vscode/.runtime/ros_logs \
ros2 launch so101_bringup sim_bringup.launch.py \
  use_gzclient:=true \
  use_rviz:=false \
  use_mock_yolo:=false \
  enable_rosbridge:=true
```

参数说明：

1. `use_gzclient:=true`
   显式打开 Gazebo GUI，适合演示
2. `use_rviz:=false`
   当前只做前端验证，不强制打开 RViz
3. `use_mock_yolo:=false`
   走真实检测链路配置
4. `enable_rosbridge:=true`
   前端实时状态和后端 ROS 通信依赖这个
5. `ROS_LOG_DIR=...`
   避免默认日志目录权限问题

### 4.2 启动后端

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws/mes_backend
mvn spring-boot:run
```

### 4.3 启动前端

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws/mes_frontend
./node_modules/.bin/vite --host 127.0.0.1
```

### 4.4 打开页面

```bash
explorer.exe http://127.0.0.1:5173
```

## 5. 运行状态检查命令

### 5.1 检查 rosbridge 连接

```bash
curl http://127.0.0.1:8080/api/ros/health
```

正常期望：

```json
{"connected":true}
```

### 5.2 检查系统状态

```bash
curl http://127.0.0.1:8080/api/system/status
```

重点看这几个字段：

1. `simRunning`
2. `gazeboRunning`
3. `rosbridgeConnected`

### 5.3 检查端口

```bash
ss -ltnp | rg ':(5173|8080|9090)\b'
```

## 7. 常见问题

### 7.1 页面显示“实时状态 未连接”

先点页面里的：

```text
连接实时状态
```

如果还不行，再查：

```bash
curl http://127.0.0.1:8080/api/ros/health
```

### 7.2 工单停在 `DISPATCHED`

这通常不是前端问题，而是 ROS 执行链没有继续回状态。

查看 ROS 日志：

```bash
tail -n 120 /home/muqiao/dev/ros2/workspaces/so101_ws/.vscode/.runtime/so101_visible_ros.log
```

### 7.3 端口被旧进程占用

先停当前默认的可见演示模式：

```bash
bash tools/e2e/stop_visible_demo_stack.sh
```

再重新启动默认模式：

```bash
bash tools/e2e/start_visible_demo_stack.sh
```

说明：

1. `start_visible_demo_stack.sh` 现在要求自己启动一套新的可见仿真
2. 如果 `9090` 已被旧栈占用，它会直接报错并要求你先停干净
3. 这样做是为了避免复用旧的隐藏仿真进程，导致 Gazebo 视角/场景状态异常

### 7.4 Gazebo 打开后黑屏或看不到工作台

先确认你不是复用了旧的隐藏仿真：

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws
bash tools/e2e/stop_visible_demo_stack.sh
```

然后重新启动可见模式：

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws
bash tools/e2e/start_visible_demo_stack.sh
```

说明：

1. 已经为 `so101_workcell.world` 固化了更亮的环境光和默认相机位姿
2. 新开 Gazebo 时应该直接看到工作台、料盒和机械臂

### 7.4 WSL 里图形浏览器打不开

先检查：

```bash
echo $DISPLAY
echo $WAYLAND_DISPLAY
```

如果只是想验证前端，不必强求 WSL 浏览器，直接用 Windows 浏览器访问：

```text
http://127.0.0.1:5173
```

## 9. 演示时建议使用的动作模板

优先使用：

```text
pick_place_default
```

原因：

1. 这是最稳定的基础演示模板
2. 不依赖颜色检测触发

不建议先用：

1. `pick_place_red`
2. `pick_place_blue`

原因：

1. 这两个依赖检测输入
2. 演示时更容易误判成系统坏了
