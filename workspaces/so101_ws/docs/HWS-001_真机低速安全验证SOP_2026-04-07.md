# HWS-001 真机低速安全验证 SOP

更新时间：2026-04-07

## 1. 目的

把当前主臂真机状态从“软件侧已到人工验证入口”推进到“人工安全验证已留证”。

本 SOP 只验证：

- 急停
- 停机
- 限位/危险边界确认
- 低速/速度缩放

本 SOP 不做：

- 放开 `allowExecute`
- 将 `commandExecutionEnabled` 改成 `true`
- 连续轨迹
- 视觉抓取
- 自由抓取
- 复杂联动

## 2. 角色分工

- 操作员：`muqiao`
- 观察员：建议至少 1 人
- 要求：操作员的手始终能在 1 秒内触达急停

## 3. 开始前硬条件

在终端先确认当前仍处于保护锁定态：

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws

bash tools/hardware/main_arm_runtime_watch_status.sh
python3 tools/hardware/check_real_hardware_preflight.py \
  --root-dir /home/muqiao/dev/ros2/workspaces/so101_ws \
  --skip-backend-compare --json
```

只有当下面几项同时满足时，才进入人工验证：

- `watcherRunning=true`
- `statusFresh=true`
- `online=true`
- `powerState=已上电`
- `calibrationValid=true`
- `homed=true`
- `allowExecute=false`
- `commandExecutionEnabled=false`

任一项不满足时，停止本 SOP，先回到软件侧排查。

## 4. 现场准备

开始前逐项确认：

- 工作台周边无人进入机械臂危险区
- 线缆没有缠绕、绷紧、挂边
- 夹爪当前位置无夹伤风险
- 主臂当前位置与桌面、支架、夹具无明显干涉
- 急停按钮位置明确且一按即达
- 若控制器支持速度档位，先切到最低速

如果现场对任一项看不清、拿不准、未确认，不继续。

## 5. 验证顺序

严格按这个顺序做，不要跳步。

### Step 1: 急停验证

目标：

- 确认急停按下后，系统进入保护态，不会继续进入危险动作。

执行：

1. 保持系统处于当前锁执行状态。
2. 在主臂无危险动作前提下，按下急停。
3. 观察控制器/驱动/指示灯/状态变化。
4. 解除急停后，确认系统不会自动恢复执行。

通过标准：

- 急停后系统保持保护态
- 没有自发动作
- 解除急停后仍不自动执行

失败即停止：

- 急停后仍有异常动作
- 解除急停后自动恢复
- 任意状态不可解释

### Step 2: 停机验证

目标：

- 确认正常停机或断使能路径可控，不会抽动、乱动、自动恢复。

执行：

1. 触发正常停机/断使能路径。
2. 观察主臂是否平稳进入停机状态。
3. 如需恢复，仅恢复到“上电但锁执行”状态。

通过标准：

- 停机过程可控
- 无抽动、无突然位移
- 恢复后仍保持锁执行

失败即停止：

- 停机过程出现不可控位移
- 恢复后自动进入可执行态

### Step 3: 限位/危险边界确认

目标：

- 确认当前姿态、可见边界、夹爪开口、线缆路径都在安全范围内。

执行：

1. 目视确认各轴附近没有即将碰撞的风险。
2. 目视确认夹爪与台面/治具/边缘距离安全。
3. 目视确认线缆在最小可预期动作范围内不会被拉扯。

通过标准：

- 当前姿态安全
- 低速最小动作范围内无明显碰撞风险
- 线缆与夹爪边界都清楚

失败即停止：

- 任一风险无法排除
- 任一边界不清楚

### Step 4: 低速/速度缩放验证

目标：

- 确认当前控制路径确实受限于低速档，不会以未知速度动作。

执行：

1. 确认速度档位、速度缩放旋钮或软件限速处于最低或安全档。
2. 若硬件支持本地微动，只允许做最小幅度、单步、低速试探。
3. 微动时操作员保持手在急停附近。

通过标准：

- 低速档明确生效
- 若做微动，则动作小、慢、可控
- 全程可随时中断

失败即停止：

- 速度档位不明确
- 微动不受控
- 无法确认缩放是否生效

## 6. 留证方式

### 全部通过时

执行：

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws

python3 tools/hardware/collect_real_hardware_safety_evidence.py \
  --root-dir /home/muqiao/dev/ros2/workspaces/so101_ws \
  --operator muqiao \
  --scenario "HWS-001 manual safety validation" \
  --notes "manual estop/stop/limit/speed checks passed on physical hardware" \
  --estop-ok \
  --controlled-stop-ok \
  --limit-guard-ok \
  --speed-scaling-ok \
  --json
```

通过后应看到：

- `.vscode/.runtime/real_hardware_safety_evidence.json` 更新
- `manualSafetyReady=true`
- `readyForManualMotionReview=true`

### 有任一项未通过时

不要带失败项的 `--*-ok` 参数，把失败现象写到 `--notes`：

```bash
cd /home/muqiao/dev/ros2/workspaces/so101_ws

python3 tools/hardware/collect_real_hardware_safety_evidence.py \
  --root-dir /home/muqiao/dev/ros2/workspaces/so101_ws \
  --operator muqiao \
  --scenario "HWS-001 failed manual safety validation" \
  --notes "describe the exact failed step and observed behavior here" \
  --json
```

这时返回非 0 是正常的，表示 `HWS-001` 还没完成。

## 7. 结束条件

只要出现下面任一情况，立即结束本轮验证：

- 有任何不可解释动作
- 速度不受控
- 急停行为不符合预期
- 现场边界看不清楚
- 线缆、夹爪、关节、台面存在碰撞风险

结束后保持：

- `allowExecute=false`
- `commandExecutionEnabled=false`

## 8. 完成后汇报口径

完成本 SOP 后，只汇报三件事：

1. 当前 preflight 是否仍然通过
2. 四项人工验证分别通过/失败/未执行
3. 是否已成功写入 `.vscode/.runtime/real_hardware_safety_evidence.json`

在 `HWS-001` 和 `HWS-002` 都有真实证据前，不讨论放行动作。
