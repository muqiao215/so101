# HWP-003 真机驱动适配层与状态桥接

## 目标

在真机目录尚未给出前，先把 SO101 的真机驱动接入面收敛成统一 contract。

本轮只解决两件事：

1. 真实驱动如何把状态桥接进现有系统
2. 现有后端如何只依赖 contract，而不是依赖具体驱动细节

## Contract 文件

运行时统一只认两个文件，位置都在：

- `.vscode/.runtime/real_hardware_status.json`
- `.vscode/.runtime/real_hardware_command_gate.json`

### 1. 状态文件

字段：

- `online`
- `controlInterface`
- `powerState`
- `estopActive`
- `mode`
- `lastError`
- `allowExecute`
- `updatedAt`

说明：

- `allowExecute` 只是“驱动侧是否认为当前可执行”的声明，不代表系统最终放行。
- 真正的最终放行，还要再经过 command gate。

### 2. 命令门控文件

字段：

- `commandExecutionEnabled`
- `reason`
- `source`
- `updatedAt`

说明：

- 这是系统级放行闸门。
- 只要这个文件是 `false`，后端展示的 `allowExecute` 就必须是 `false`。
- 这样可以把“驱动在线”和“系统允许执行”彻底分开。

## 当前软件落地

### 1. 统一 contract 模块

- 文件：`tools/hardware/real_hardware_contract.py`
- 作用：
  - 归一化状态字段
  - 归一化 gate 字段
  - 统一写出运行时 contract 文件

### 2. 兼容旧入口的状态写入器

- 文件：`tools/hardware/write_real_hardware_status.py`
- 当前行为：
  - 仍可被 `prepare/start/stop` 复用
  - 现在会同时写：
    - `real_hardware_status.json`
    - `real_hardware_command_gate.json`

### 3. 新的桥接入口

- 文件：`tools/hardware/bridge_real_hardware_adapter.py`
- 支持三类来源：
  - `--source fake`
    - 给软件联调、假数据、自测使用
  - `--source file`
    - 给“真机目录内已有状态 JSON 文件”的场景使用
  - `--source command`
    - 给“真实驱动命令输出 JSON”的场景使用

这三类入口分别对应：

- mock/fake 接入点
- 真实目录接入点
- 真实接口接入点

## Backend 侧约束

- 文件：`mes_backend/src/main/java/com/so101/mes/service/SystemControlService.java`
- 当前行为：
  - 后端读取状态文件
  - 后端同时读取 command gate 文件
  - 最终 `allowExecute` 计算方式变为：
    - 状态文件 `allowExecute=true`
    - 且 gate 文件 `commandExecutionEnabled=true`
    - 且 `online=true`
    - 且 `estopActive=false`

这意味着：

- 驱动自己说“我能动”，不再足够
- 必须再经过系统级放行闸门
