课题名称  
基于ROS2和LeRobot SO-101的小型智能制造MES系统设计与实现

一. 课题方向与涵养班培养目标关联性  
本课题属于“机器人控制 + 机器视觉 + 制造信息化（MES）”的交叉方向。项目不仅要求掌握ROS2通信机制、机械臂控制、Web后端与前端开发、数据库与实时消息推送等工程技术，还要求在有限资源条件下完成可落地的系统方案，体现从单点技术到系统集成的能力。  
在“技术应用能力”方面，课题覆盖建模、控制、检测、调度、可视化全流程，强调可运行与可复现；在“伦理思辨能力”方面，需考虑误检误触发、异常停机、任务追溯、人工接管等安全与责任边界问题；在“实践调研能力”方面，需结合实验室条件进行技术选型与方案取舍，如选择固定工装定位与预设轨迹策略，优先保证演示稳定性与工程可实现性。  
因此，本课题与涵养班“技术 + 场景 + 责任”的培养目标高度一致，能够训练学生的工程实现、系统思维与问题闭环能力。

二、本课题解决的主要问题  
1．**传统控制方式自动化程度低**  
人工逐步操作效率低、重复性差、对操作者经验依赖强，难以形成稳定连续的生产流程。本课题通过MES工单驱动与机械臂自动执行机制，实现标准化任务下发与状态闭环。  
2．**设备控制层与业务层耦合过高**  
将ROS2控制逻辑直接嵌入Web业务进程，容易造成并发复杂、维护困难与扩展受限。本课题采用“ROS2设备层 + MES业务层”进程分离，借助rosbridge进行协议桥接，降低耦合。  
3．**视觉结果难以直接转化为动作**  
仅有检测结果无法直接驱动机械臂作业。课题建立“检测类别 -> 动作模板 -> 轨迹执行”的映射机制，使视觉信息可被业务逻辑直接消费。  
4．**仿真到实机迁移成本高**  
很多项目仿真可跑、实机重构。本课题基于ros2_control统一控制接口，保持上层调用一致，降低迁移风险与调试成本。  
5．**缺少可追溯验证体系**  
仅凭“跑通一次”难以支撑工程评价。本课题建立任务清单、进度日志、测试记录和关键指标（成功率、时延、稳定性）作为验收依据。

三、解决问题的主要方法与技术路线  
1. 总体方案设计  
明确系统指标与功能边界，构建“感知—决策—执行—反馈”闭环架构，形成系统框图、数据流和部署拓扑。  
2. 硬件系统设计与实现  
采用SO-101机械臂、USB摄像头和固定工装，完成供电、通信与安装布局设计，优先保障稳定性与可维护性。  
3. 软件程序设计  
按模块实现ROS2控制节点、YOLO检测节点、Spring Boot后端、Vue前端；定义统一接口与消息格式，完善异常处理与日志。  
在实现过程中采用“先最小可用、再逐步增强”的迭代策略：第一阶段打通单机闭环，第二阶段补充异常处理与状态一致性，第三阶段进行性能压测与演示固化，确保每一阶段均有可验证成果。  
4. 控制算法应用与优化  
使用MoveIt2进行路径规划与执行，结合关节约束、碰撞检测和速度参数调优；采用“visual用STL、collision用简化模型”提高规划效率。  
5. 上位机/人机界面设计  
实现工单创建、状态监控、检测结果展示、统计查询等页面，通过WebSocket实现实时反馈。  
6. 系统调试与实验验证  
按“分模块调试—子链路联调—全链路验证”推进，分别在仿真与实机条件下测试，输出可复现实验记录与证据包。
验收时重点关注三类指标：功能完整性（链路是否闭环）、工程稳定性（连续运行是否可靠）、结果可追溯性（日志与记录是否充分）。通过量化指标与问题清单，形成最终评估结论。

四、课题任务要求  
1. 实现“工单下发—视觉确认—轨迹执行—状态回传”完整闭环。  
2. ROS2设备层内部采用标准Topic/Service/Action通信。  
3. MES业务层通过rosbridge与ROS2进行松耦合交互。  
4. 完成Gazebo仿真验证，并具备向实机迁移能力。  
5. 前端支持PC浏览器访问，具备实时状态与检测结果展示。  
6. 形成可追溯文档：任务清单、日志、测试结果、关键截图。  
7. 说明书需完整呈现架构设计、关键实现、实验分析与改进方向。
